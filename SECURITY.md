# Security policy

## Supported versions

Tessera is pre-release software with no supported stable release. Security work currently targets the latest `main`. Older snapshots are not maintained, and the project is not ready for use as a primary desktop shell.

## Confidential vulnerability reporting

GitHub private vulnerability reporting is enabled for this public repository. Use [Report a vulnerability](https://github.com/redstone-md/tessera/security/advisories/new), also available under **Security → Advisories**, instead of a public issue for exploit details or sensitive information. Reports are shared privately with maintainers; there is no response-time commitment yet.

Include the affected commit/release, Windows version/build, expected impact, and a minimal reproduction with personal data removed. Do not include credentials or unrelated private desktop output, and do not send reports to GitHub `noreply` addresses.

If GitHub's confidential form is unavailable, open only a high-level public request to arrange a safe follow-up; do not publish exploit details or secrets there. Allow coordinated assessment and disclosure before sharing vulnerability details publicly.

## Security scope

Relevant areas include Win32 memory safety, FFI callback boundaries, DPI-context restoration, untrusted desktop text, dependency vulnerabilities, and future window-management or plugin permissions.

The implementation observes desktop state, calculates synthetic layouts, and presents a native dock/launcher. Observation remains read-only; scoped out-of-context WinEvent notifications trigger coalesced refreshes, not input interception. Explicit activation revalidates HWND/PID and respects foreground restrictions; launch resolves a trusted catalog item. Explicit Appearance Save/dock-pin/launcher-favorite/display-mode actions persist a complete per-user preference record bounded to 16 KiB including its newline; invalid/future/damaged startup files disable all ordinary writes for that session, never implicit recovery or replacement. Current strict schema 3 groups launcher mode and favorites; separate strict schema-1/schema-2 readers migrate in memory only, and the first successful explicit save writes schema 3. See the [settings recovery and downgrade notes](docs/alpha-testing.md). Experimental shell activation requires a separate installer action, verified backup, and a production two-heartbeat runtime probe; its current-user override is restored by the native supervisor or independent scripts. No DWM replacement, automatic layout, plugin execution, implicit autostart, or security-setting changes are implemented. Activation is non-atomic; same-process handle reuse remains a risk.

In unpublished development, launcher launch/favorite authorization checks current logical result keys and the full retained trusted catalog, not instantiated Slint rows or keys displayed only on another surface. All/search inventory and saved-order Favorites resolution are no longer capped at 64; unresolved saved favorites cannot authorize execution. Native catalog discovery still stops at 1,024 entries before deduplication, and the recovery Panel's independent 64-application projection remains bounded. Virtualization changes presentation demand, not the trusted launch boundary, and adds no desktop observations, polling, timer or input hook.

The launcher display-mode action changes only the saved mode in a clone of the complete applied preferences; it cannot persist an unsaved appearance preview or add application-launch authority. Repeated already-applied intent saves nothing. Fullscreen uses validated physical monitor bounds and the existing activatable owned-window role, not an appbar, exclusive fullscreen, input hook or new worker/timer. Missing bounds reject Fullscreen before persistence. Disk-save failure preserves applied state and geometry; successful persistence followed by native presentation failure is reported as saved-but-unpresentable, not falsely rolled back. Primary-monitor placement and native focus/accessibility remain limited and require interactive Windows validation.

In unpublished development, Favorites reorder uses a private typed in-window drag payload carrying immutable gesture identity/revision, not an external text/path launch target or a retained tile handle. Completion revalidates the current empty-query Favorites view, exact source/anchor identities, saved membership and trusted catalog before one changed full-record save. Preview grants no launch authority and performs no persistence; rejected, cancelled or no-op intents save nothing. Unresolved favorites retain their saved slots, and failure restores applied order without silently dropping IDs or persisting appearance preview. A shared single-flight gate rejects nested Appearance/Pin/Favorite/Display/Order writes of stale complete records. Hide/reopen, query/view/catalog changes, membership changes and incompatible coordinate revisions invalidate gestures; native teardown is deferred through the public pointer-exit path outside active dispatch. Successful saves reconcile a currently visible reopened session from current applied data, never the old preview or an extra show/focus request. Controlled native input/persistence checks pass; this is not certified Windows/OLE drag-and-drop or a new folder/power capability.

The unpublished, controlled-verified drag-feedback layer is presentation only. Its retained source image/label is captured from a validated canonical application record; an overlay key cannot authorize launch or reorder. Only the SDK's immutable typed hover payload can reveal it, not a payload-free dragging-change callback. The full-window observer validates the current private token, native dragging and geometry but always rejects drops and updates only visual coordinates, never grid targets, autoscroll or persistence. Feedback and its favorite corner have no input/focus/Tab/visible accessibility action. The source slot is retained but hidden and passive: Slint keeps raw hidden static-role AX nodes, so retained/deferred actions are guarded and existing stable-grid focus is established before hiding. End/cancellation synchronously clear the descriptor and restore source paint; deferred native teardown epochs cannot erase a newer gesture or resurrect an old session. Native input, stale-handle, payload-rejection and cleanup fixtures pass; actual Windows AX/OLE remains unverified. No extra owned window, native lease, host focus/show request, desktop observation, external payload or persistence format is introduced.

Source appearance is transient presentation metadata, not payload or persistence authority. One finite-positive scalar is captured on validated native Down before source-image conversion into private gesture state. Later metadata/descriptor changes cannot change the captured value or authorize a hover/drop; invalid appearance leaves no gesture/image conversion and restores reorder eligibility. End/cancellation clears the scalar with the descriptor. Scale changes paint only: source-slot dimensions, collision and pointer-minus-hotspot geometry remain independent.

The unpublished User popup has an independent closed known-folder capability, not application launch or UI path authority. Its seven folder IDs and current-session opaque row keys must resolve to confirmed private Ready targets. A dedicated bounded STA queue validates private provider/category/revision provenance, freshly resolves the known folder and compares canonical identity before opening a fresh PIDL; it does not execute UI-provided paths, scripts or commands. Native paths and provider messages are excluded from GUI feedback. Accepted requests retain their flight across hide/reopen, stale completions cannot project into a new session, and retry never automatically repeats an open. No preference save, catalog observation, file listing, directory watch or account operation is implied. Shell acceptance is not visible-Explorer confirmation; native handlers can block the worker and cannot be forcibly cancelled after dispatch.

The unpublished Calendar capability reads system-local Gregorian date and bounded user-locale labels on a dedicated nonblocking worker. It never sets the clock, timezone or locale, parses clock text, fabricates dates/names, observes windows or persists selection. Documented empty calendar-name records resolve only through matching native locale queries; native errors/malformed data never authorize a guessed fallback. Private current projection keys gate navigation/day/month actions; one accepted read survives hide/reopen without stale publication, and the minute refresh stops while hidden or failed. Calendar/User/Quick/Context share a post-show acceptance boundary: invalid/cancelled placement retains the other popup, while a genuinely visible popup displaces it even when foreground was refused. Source coordinates are checked before capability reads; headless tests do not pretend a backend's no-op position setter is real native geometry.

The unpublished reserved Show Desktop effect is explicit and non-idempotent. It uses one fixed Shell CLSID/IShellDispatch6 operation behind a bounded capability, not UI-supplied paths, HWND restore lists, synthetic input or recovery commands. Only visible, live Dock intent can acquire it; pending duplicates and Return repeats cannot automatically retry after completion. Native request-local strict STA/Shell resources stay thread-confined and release before callback or idle receive; there is no unsafe Send/Sync or GUI-thread join. Activation uses `CLSCTX_INPROC_SERVER | CLSCTX_DISABLE_AAA`, with no local/remote fallback or global security/elevation mutation. A fixed COM class/context is not cryptographic assurance of registered code, and native success does not prove visible windows or a known desktop state. Accepted jobs can finish after UI teardown and cannot be forcibly cancelled; arbitrary provider messages are excluded from UI. Its request-scoped verification is independent of the known-folder idle-wait correction below.

The known-folder worker's persistent STA now uses a private owned event and message-aware waiting, with bounded all-thread message batches and no service/fault lock spanning dispatch or consumer completion. The event carries only a wake hint, never a folder target or authorization; native targets and COM stay on the worker and release before terminal callback draining. A failed signal after queue acceptance cannot become an immediate rejection: its completion remains owned and is fulfilled once. A 250ms local safety wait covers missed fault/disconnect wakes without observing folder or desktop data. Final host drop disconnects before signaling and never joins. Native handlers/message dispatch may still stall; this is neither a timeout/cancellation guarantee nor Windows runtime certification. `SEE_MASK_NOASYNC` is not a general Shell-namespace completion guarantee.

The first unpublished Recycle Bin capability has only fixed aggregate read, numeric namespace Open and invalidation watch; it has no Empty/delete method, caller-supplied root/path/flags/HWND, application launch or recovery authority. Only successful real Dock placement and live visible intent admit requests. Checked signed native counts and SDK-sized query buffers supply confirmed state; query failures never fabricate an empty bin. Open uses an owned `VT_I4` `ssfBITBUCKET` value and base `IShellDispatch`, with request-local strict STA and native release before callback/idle. Dispatch success is not Explorer visibility or cryptographic registration assurance, and numeric Open may initialize missing Shell resources. A separate watcher owns its fixed PIDL, private message-only window, registration and stop event on its own thread. New-delivery locks release before consumers; opaque nonreused userdata tokens, not raw context pointers, retire before native cleanup/reentry. Guard drop is nonblocking; admitted late callbacks are generation-checked, and hidden/closed UI cannot replay Open or resurrect itself. Its 250ms wait checks local stop state, not bin data. A positive registration cookie does not certify notification coverage for every queried volume, removable/mount change or Shell restart. Native handlers may stall; no forced cancellation, execution deadline or GUI join is promised. A future confirmed mutation needs separate native owner-lifetime authority and real readback, not optimistic zero.

Avoid publishing desktop captions, file paths, screenshots, or tokens as part of a report. Please allow maintainers to assess a report and coordinate disclosure before making exploit details public.

## Security-product compatibility

All Windows executables request `asInvoker` with `uiAccess=false`; normal use does not require elevation. There are no low-level global input hooks, injection, desktop polling, network operations, or toolkit inspection server. Only the supervisor's own failed/diagnostic GUI child may be terminated. Registry recovery refuses unrelated subsequent shell changes and retains the backup; a blocked supervisor cannot execute fallback, so independent Task Manager recovery is required. Read the [distribution and trust policy](docs/distribution-and-trust.md).

Public test alphas are explicitly unsigned and not certified as antivirus-safe. The prerelease includes corresponding source and checksums; some protected machines cannot run it until trusted signing is available. Never disable Windows protection or add exclusions for a test. Investigate detections before calling them false positives, and obtain approval before uploading modified private artifacts or private desktop data to a vendor or third-party scanner.
