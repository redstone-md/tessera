Reference-only current SVG, independently downloaded into analysis cache:

SHA-256: e24878ccca44c48697aa690d4e30caa369eea99790417207bdb25e0c819491f3
The current reference is not redistributed here; no current path geometry
was inserted into, or relabeled as, the retained historic artwork.

Renderer: installed FFmpeg 7.1.5 (Debian 7:7.1.5-0+deb13u1), librsvg 2.60.0
(Debian 2.60.0+dfsg-1), Cairo 1.18.4 (Debian 1.18.4-1+b1).
Both independently downloaded, unmodified SVGs were rasterized directly at
16x16, 32x32, and 64x64 pixels, default black fill/currentColor, transparent
background, origin-aligned full 24x24 viewBox. No bitmap rescaling was used.
For each file and size N, the analysis command was:
  ffmpeg -hide_banner -loglevel error -width N -height N -i FILE.svg -frames:v 1 -y FILE-N.png
RGBA pixels and 8-bit alpha were compared with existing Pillow/NumPy tools.
Bounds below are [left, top, right-exclusive, bottom-exclusive].

32   | 55 /1024              | 16                   | 0.16015625                | 164                 | 0

Nonzero-alpha bounds (old and current are the same at each size):

Alpha >=128 bounds (old and current are the same at each size):

For a 16 logical-pixel slot, the 1x/2x studies (16/32 physical pixels) show
matching half-coverage silhouettes and matching raster bounds, but actual
antialiasing pixel values differ. This supports an approximate close visual
match, not equal appearance, identical shape geometry, or pixel equivalence.
The old arc-based path and current cubic path are distinct. At 64 pixels even
three half-coverage silhouette pixels differ. These results are specific to
the stated renderer, alignment, color, and sizes; they do not establish
parity in the application's native renderer, fractional positions, different
DPI, or compositing. Native visual integration remains a separate decision.
